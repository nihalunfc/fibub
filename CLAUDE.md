# Notes for Claude sessions in this repo

fibub.com (Free In-Browser Utility Bubble; free, open-source tools that fill the gaps people and workplaces have): tools for documents, money, data, everyday tasks and science that run entirely in the browser. Apache License 2.0 with a NOTICE file that credits fibub and nihal (nihal's choice, 2026-11-08: anyone may use it, also commercially, but must keep the credit); OpenNGC catalogue data is CC-BY-SA 4.0. Astro 5, static, served by a Cloudflare Worker with static assets (`wrangler.jsonc`; the Worker script only runs for `/api/*`; Cloudflare builds and deploys `main` on every merge). Owner: nihal (GitHub `nihalunfc`).

## House rules
- **Nothing about the user is stored, ever** (nihal, 2026-11-06). Only anonymous daily totals (tool, file type, size range, device, OS, browser, country, outcome) go to `data/stats/` and the public `/stats/` page. No IPs, IDs, cookies, timestamps finer than a day, or return-visit tracking.
- **Public counters** (nihal, 2026-11-09): views for every page (by address) and uses for every tool, kept per day (UTC) and all-time in a Durable Object (`worker/index.ts`, the site's only server code, reached only at `/api/*`); weeks, months and years are added up from the days. No IP, time of day, device or ID is read or stored. On the site, the public sees only the whole-site total on the home page and each page's own views under its title (uses are counted but not shown, for now). Every day `.github/workflows/views.yml` copies the counts into `data/views/` (day files plus daily/weekly/monthly/yearly/all-time CSVs) so they are public in the repo; nihal will use them for site analysis and to sell sponsor slots. New pages and tools are counted automatically (`dist/pages.json` from `scripts/list-pages.mjs` lists what may be counted; a use is the first button press, typed value or chosen file inside `.tool-ui` per page load, `src/scripts/counts.ts`). Nothing to add per tool or page. The home page also shows the 10 most used tools (`GET /api/top`: ranked by uses, then views; hidden until the counter answers) and site totals worked out at build time by `src/lib/totals.ts` from the tool files and `src/data/curricula.ts` (curricula and courses; zero totals are left out). To add a school curriculum (Canada, USA, UK) or a course, edit `src/data/curricula.ts`; the totals follow.
- A tool may keep the user's own data in their browser (localStorage) so it is there next visit, only when the page says so plainly, it never leaves the device, and there is a way to clear it (e.g. planner, budget "Remember my numbers" box, off by default for money data). Boxes that keep typed records, drafts or tags start unticked, so nothing is stored until the visitor opts in (2026-11-09: #820, #827 and #856 switched to opt-in).
- **Only tools that run fully in the browser** (nihal, 2026-11-06). If a feature needs a server to process user files (e.g. layout-perfect PDF to Word), leave it out.
- **Nothing leaves the device.** Tools never upload files or entered data, never call third-party APIs with user data, and work offline once the page has loaded. Public data feeds (e.g. daily currency rates) are fine if they send nothing about the user.
- **Legal everywhere we target** (Canada, India, US, UK, Gulf states). Never build: video/music downloaders, password or DRM removers, VPN/proxy tools, betting or gambling tools, crypto trading signals, anything that stores ID documents.
- **Ads:** `ads: false` on any tool that opens personal files or bank data. No ad code anywhere until nihal approves an ad network.
- Region rules (tax rates, photo sizes, gratuity) show the source and the date checked, and say "check the official source".
- Plain, friendly English. Explain what a setting does in one line.
- Phone first: test at 375 px wide; no sideways scroll.

## Adding a tool
0. **Start from the generator** (nihal, 2026-11-10, to save tokens): `npm run new-tool -- <id> --name "..." --shelf <shelf> [--section <s>] [--code T721] --related a,b,c` writes guide.md, Tool.astro and tests/tools/<id>.mjs with the next free ID code (give parallel builders their own codes with `--code` or `--code-from`); fill the TODOs. Learn tools get the shared engine: `src/lib/learn/quiz.ts` (number, expression, choice and text answers) and `src/lib/learn/sim.ts` (canvas, level switch, play loop). New tools use these instead of writing their own quiz or canvas helpers; the older per-builder quiz libs move over later.
1. Make `src/tools/<id>/` (the id is the URL slug, e.g. `compress-pdf`).
2. `guide.md`: frontmatter (`code`: the tool's permanent ID, shown as #T12 or #L3; never change or reuse one, even if a tool is removed. nihal refers to tools by it, e.g. "make the buttons better on #T3". **ID scheme (nihal, 2026-11-10):** one letter per area, counted without gaps: T = Tools tab (all shelves except learn), L = Learn; listed in `CODES` in `src/site.ts`, explained with a chart at `/tools/#ids`. A new area gets a free capital letter (never I or O); if its letter is taken it gets a short code like TCH. `num` is the old plain number (kept as a search alias, "#3", and as the order tools were added in); the generator fills both. `node scripts/renumber.mjs` gives a code to any tool that has a num but no code. `name`, `shelf`: money | documents | everyday, `title` as people search it, `summary`, `status`: live | soon, `ads`, `order`, `updated`, `works`: offline | online (offline = keeps working with no internet once the page is open; test it), and for live tools `flow`: 3 or 4 steps of `{ icon, label }`, labels up to 12 characters, icons from `src/lib/icons.ts`; it is the picture at the top of the tool page and must stay on one row on a 320 px phone) and a body of 300+ words: how to use it, what each option does, a worked example, FAQs.
3. `Tool.astro`: the UI and its `<script>`. Load heavy libraries with `import()` so the page stays fast.
4. Add checks for it in `tests/run.mjs`, and run `npm run images` to make its share image (`public/og/<id>.png`: tool name, fibub.com, FREE, NO SIGN-UP). Commit the image.
5. Science tools need a `section` (listed in `SECTIONS` in `src/site.ts`); each section belongs to a subject (`SUBJECTS`: physics, astronomy, chemistry, ... 16 in all, from the science ideas list). Subjects get their own page at `/science/<subject>/` once they have a live tool, so a tool id may never equal a subject id. The build fails on an unknown section, a science tool without one, or a tool id that clashes with a subject.
6. **Cross-link related tools (nihal's hard rule):** list them in `related:` (tool ids). Links show both ways ("Works well with" and Related tools); the build fails on an unknown id.
   **Link in the text too, like an encyclopedia (nihal, 2026-11-09):** end the guide's first section with one sentence that sends readers to 2 or 3 related tools for the step before or after, written as `[[tool-id]]` (shows the tool's name) or `[[tool-id|your words]]`. Elsewhere, the first mention of any tool's name links itself (`src/lib/autolink.mjs`, at most 8 per guide). Only where it helps; never a list of links. A guide without its own sentence gets a plain "It works well with ..." sentence from `related:` until one is written. Tool styles use `<style is:inline>` (not `is:global`) so each page carries only its own CSS.
7. Tools that make a report use `src/lib/report.ts` (sections of facts, tables and canvas figures) and `components/Downloads.astro` for PNG, PDF and Word downloads.
8. `npm run build && npm test` must pass, then open a PR. The tool appears at `/<shelf>/<id>/`, on its shelf page and on the home page automatically.

## Search engines and speed (nihal, 2026-11-09)
- Pages must load near-instantly from a search result. Keep each page's HTML under 120 KB (`npm test` checks); the menus' tool lists live in `/nav/` and load the first time someone reaches for a menu (`loadNav()` in `src/scripts/site.ts`), never in every page. CSS is in shared cached files; links prefetch on hover or touch.
- Search titles and descriptions come from `src/lib/seo.ts`: the part of `title` before the colon plus "free online tool", and the summary cut to 160 characters. If either reads badly, set `seoTitle` (60 max) or `seoDescription` (160 max) in guide.md.
- **One page per search** (nihal, 2026-11-14): a tool page targets the doing searches ("internet speed test"), its blog guide the understanding searches ("what is a good internet speed"); never the same main phrase on two pages. Rules in `src/blog/README.md`; phrases per page in `/mnt/project-files/fibub/seo/keyword-map.md`.
- Structured data (JSON-LD) is automatic: WebApplication and breadcrumbs on tool pages, CollectionPage on shelves and subjects, WebSite and Organization on home. Never add fake ratings or reviews.
- Search Console and Bing Webmaster Tools are verified by DNS, with no code on the site. Never add Google Analytics, Tag Manager or any tracking script.
- IndexNow: after each merge that touches `src/tools/`, `.github/workflows/indexnow.yml` waits for the deploy and sends the changed tool pages (plus home and their shelves) to IndexNow (Bing and others) with `scripts/indexnow.mjs`; run the workflow by hand to send every page. The key file is `public/b544da555d964ccdfafaadfab66a850b.txt`; never rename it. It sends only fibub's own addresses.
- Every `Tool.astro` uses `<style is:inline>`, never `is:global` (`npm test` checks).

## Site rules
- **No tool lives on both sites** (nihal, 2026-11-07). Everyday public tools go on fibub; ambitious career prototypes go on nihalsulaiman.com. Link between them only where useful. nihal's name appears only on the About page; the footer says "Developer" and links to the portfolio.
- Header: drop-down menus per shelf on computers; a search button on every screen opens the menu panel.
- **Bottom bar on every page, phones and computers** (nihal, 2026-11-09; `components/TabBar.astro`, `styles/tabbar.css`, areas in `AREAS` in `src/site.ts`): Learn, Tools, Home, Blog, Menu. Phones: five tabs, icon over name. Computers: a taskbar along the bottom with the buttons side by side in the middle. Above it, a smaller bar of the current area's sections (left out on tool pages). Menu opens the menu panel (search, My tools, then folding Learn, Tools > shelves > subjects, Blog, About); half the screen wide on phones, and the page behind keeps scrolling. On touch screens the bars hide while typing. New pages join an area by path (`match`); anything else is Menu.
- **Learn** (`/learn/`): for school students, Class 8 to 12, following NCERT topics (not affiliated; never copy textbook text or figures): Class 8 to 12, Experiments, Courses, Languages. University (graduate/master's) material comes later. **Blog** (`/blog/`, was News until 2026-11-10; `/news/` redirects): articles in `src/blog/<kind>/<slug>.md` at `/blog/<kind>/<slug>/` (rules for writers in `src/blog/README.md`): `guides` (one per tool, slug = tool id; the tool page links to it as "Read the full guide"), `together` (jobs that take several tools), `kids` (for school students, per NCERT chapter), `discoveries` (3 a day from open-access CC BY papers, own words, no copied tables or figures, preprints flagged); plus the newest tools, change log and stats. Articles link like an encyclopedia: `[[tool-id]]`, `[[blog:<kind>/<slug>]]`, and tool names link themselves (`src/lib/autolink.mjs`); `scripts/check-links.mjs` fails the build on a bad link or `tools:` id. Every tool page lists the articles that mention it.
- Every tool page has a **Bookmark this tool** button. Browsers cannot open their bookmark box from a script, so it shows Ctrl/⌘+D (or the share sheet on phones) and offers an optional "pin to My tools" (tool ids only, localStorage `fibub-mytools-v1`, with a Clear button).
- Astronomy pages share the place and night (`src/lib/astro/state.ts`, `components/SkyPlace.astro`). Times show in the visitor's own time zone by default, with a "Times in" switch (the place's local time or any zone); the night itself is the place's own night (from its longitude), whatever zone is shown.
- **Red light for night use** (`html.red-mode`, kept for the tab, switched on before paint by `public/theme.js`, button in the header next to the light/dark switch): dim pure red on black only, no green or blue light; photos go through the `#red-night` filter. Keep it that way for dark-adapted eyes.
- **Built for hundreds of tools.** The home page never lists every tool: search box (site-wide, from `/tools.json`, also in the header panel on every page; "#T3" or "T3" finds tool T3; old numbers like "#3" still work), My tools, then a block per shelf. Small shelves list their tools; Science lists its subjects. Each subject page lists its tools by section. The desktop Science menu shows subjects, then each section's first 3 tools and an "All N" link. The phone/desktop Tools panel has search, My tools and folding shelves (Science folds to subjects).
- A star adds a tool to **My tools**; "Show only my tools" hides the rest until "Show all" (flag `fibub-focus-v1`, this browser only). The Tools panel follows the same switch.
- **Cell towers near you** (#T952, nihal 2026-11-14): `public/cells/` holds 1° tiles of OpenCelliD cells (CC BY-SA 4.0) grouped into ~1 km squares per carrier for Canada, India, the UK and the USA, built by `scripts/cells/build-tiles.mjs` and refreshed monthly by `.github/workflows/cells.yml` (needs the `OPENCELLID_TOKEN` secret). The page fetches only the tiles for the area; the exact location stays on the device. Checks: `node tests/cells.mjs`.
- Pure maths for science tools lives in `src/lib/sci/` as plain TypeScript with no DOM, checked against published worked examples in `tests/sci.mjs` (`node tests/sci.mjs`, part of `npm test`).
- **Install as an app** (nihal, 2026-11-13): `public/site.webmanifest` (standalone, maskable icon from `npm run images -- --icons`), service worker `src/sw.js` copied to `dist/sw.js` by `scripts/make-sw.mjs` after each build (pages network-first, so deploys show at once; kept copies offline; `/_astro/` and `/ocr/` cache-first; never `/api/`). `/offline/` lists kept pages; `/app/` explains installing; any `[data-install]` link opens the browser's install box, or the Share > Add to Home Screen steps on iPhone (`src/scripts/install.ts`). No pop-ups: installing is only from those links. In the installed app (`html.is-app`) install links hide and a Back button shows. Checks: `node tests/pwa.mjs`.

## Brand
Look (nihal, 2026-11-07): plain black on white, professional, nothing that reads as an AI template (no gradients, glows). Colour for meaning (good, warning, error), in charts, and (nihal, 2026-11-09) one strong, cool colour per area that passes WCAG AA: Learn teal, Tools blue, Home violet, Blog amber, Menu slate, used for its tabs, buttons and links (`--accent`), with lighter versions in dark mode. System fonts only: no Google Fonts or other outside fonts or APIs. A header switch turns the page dark: black and white swapped, no blue (`html[data-theme=dark]`, set before paint by `public/theme.js`, kept in this browser as `fibub-theme`). The site no longer follows the system dark setting.
Logo: a black-and-white bubble cluster (nihal chose option A, one colour, 2026-11-06), in `src/lib/brand.ts`. `npm run images` rebuilds the favicons and share images from it.

## Security
`public/_headers` sets HSTS and a strict Content Security Policy (scripts only from this site and Cloudflare Web Analytics). Don't add inline scripts or outside script hosts without updating it, and keep `connect-src` tight.
